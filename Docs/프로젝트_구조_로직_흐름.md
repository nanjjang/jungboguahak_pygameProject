# 프로젝트 구조와 로직 흐름 설명

이 문서는 현재 Pygame 프로젝트를 처음 읽는 사람이 “어떤 파일이 무슨 역할을 하는지”, “게임이 어떤 순서로 실행되는지”, “플레이어/적/전투/스테이지/화면이 어떻게 연결되는지”를 이해할 수 있도록 정리한 문서입니다.

표기 규칙:

- `@game/src/...`처럼 `@`가 붙은 것은 실제 코드 파일 위치입니다.
- “개념”은 코드가 왜 이렇게 나뉘었는지 이해하기 위한 설명입니다.
- “흐름”은 런타임에서 실제로 어떤 순서로 호출되는지 설명합니다.

---

## 1. 전체 실행 흐름 한눈에 보기

가장 큰 실행 순서는 아래와 같습니다.

```text
@game/main.py
  -> @game/src/game_app.py run_game()
    -> pygame 초기화
    -> 타이틀 화면
       @game/src/title_screen.py show_title_screen()
    -> 난이도 선택 화면
       @game/src/setting.py select_difficulty()
    -> GameState 생성
       @game/src/game_state.py GameState
    -> 메인 게임 루프 반복
       1. 입력 읽기
          @game/src/game_input.py read_frame_input()
       2. 게임 상태 업데이트
          @game/src/gameplay.py update_gameplay()
       3. 화면 렌더링
          @game/src/game_renderer.py render_game()
       4. 화면 갱신
          pygame.display.flip()
```

게임 플레이 한 프레임의 흐름은 더 자세히 보면 아래와 같습니다.

```text
입력 이벤트 수집
  @game/src/game_input.py
    ↓
플레이어 업데이트
  @game/src/kirby.py Kirby.update()
    - 이동
    - 점프/호버
    - 흡입
    - 삼키기/뱉기
    - 펀치/킥 콤보
    - 능력 빔
    ↓
플레이어가 만든 투사체 생성
  @game/src/gameplay.py -> @game/src/projectile.py
    ↓
적 업데이트
  @game/src/enemy_system.py -> @game/src/enemy.py
    - 가까운 적만 적극 AI 수행
    - 적 투사체 생성
    ↓
투사체 업데이트
  @game/src/projectile.py
  @game/src/enemy.py EnemyProjectile
    ↓
전투 충돌 판정
  @game/src/combat_system.py
    - 플레이어 투사체 vs 적
    - 빔 vs 적
    - 근접 공격 vs 적
    - 적/적 투사체 vs 플레이어
    ↓
스테이지 전환 확인
  @game/src/stage.py StageManager.update()
    - 문 앞에서 ↑ 입력
    - 클리어 애니메이션
    - 다음 스테이지 입장
    ↓
카메라/데미지 숫자 업데이트
  @game/src/game_state.py
    ↓
렌더링
  @game/src/game_renderer.py
```

## 3. 진입점과 앱 실행

### @game/main.py

역할:

- 프로그램의 가장 바깥 진입점입니다.
- `main()`이 `@game/src/game_app.py`의 `run_game()`을 호출합니다.
- `raise SystemExit(...)`로 게임 종료 코드를 운영체제에 전달합니다.

흐름:

```text
python game/main.py 실행
  -> main()
  -> run_game(difficulty)
```

여기에는 게임 로직이 거의 없습니다. 실제 게임 로직은 `@game/src/game_app.py`에서 시작됩니다.

### @game/src/game_app.py

역할:

- Pygame 초기화
- 화면 창 생성
- 타이틀 화면 실행
- 난이도 선택 실행
- `GameState` 생성
- 메인 게임 루프 유지

핵심 함수:

- `run_game(difficulty=None)`
- `_resolve_difficulty(difficulty, screen, clock)`

실행 흐름:

```text
pg.init()
screen = pg.display.set_mode(...)
clock = pg.time.Clock()
font 준비

if difficulty is None:
    show_title_screen()
    QUIT이면 종료

difficulty = select_difficulty()
GameState 생성

while running:
    clock.tick(FPS)
    actions = read_frame_input()
    update_gameplay()
    render_game()
    pg.display.flip()
```

중요 개념:

- `difficulty`를 외부에서 직접 넘기면 타이틀/난이도 선택을 건너뛸 수 있습니다.
- 일반 실행에서는 `difficulty=None`이므로 타이틀 화면과 난이도 선택 화면을 거칩니다.
- 게임 종료는 `pg.quit()` 후 `0`을 반환하는 방식입니다.

## 4. 전역 설정과 리소스 로딩

### @game/src/constants.py

역할:

- 화면 크기, FPS, 속성 데이터, 난이도 데이터, 적 데이터, 키 바인딩을 한 곳에 모읍니다.

주요 값:

- `SCREEN_WIDTH = 1000`
- `SCREEN_HEIGHT = 600`
- `FPS = 60`
- `ELEMENTS`
- `DIFFICULTY_SETTINGS`
- `ENEMY_DATA`
- `KEYS`

`ELEMENTS` 개념:

```text
fire
electric
water
earth
star
```

각 속성은 색, 라벨, 투사체 속도, 투사체 크기, 중력, 데미지를 가집니다. 예를 들어 `fire`의 투사체 속도나 데미지를 바꾸고 싶으면 이 파일의 `ELEMENTS["fire"]`만 보면 됩니다.

`DIFFICULTY_SETTINGS` 개념:

- `easy`, `normal`, `hard`의 적 속도/체력/데미지/탐지 거리/쿨다운/반응 시간/조준 오차/생성 보너스를 정합니다.
- 적 AI와 스폰 수가 이 값을 사용합니다.

`ENEMY_DATA` 개념:

- 적 종류별 스프라이트 파일명, AI 타입, 기본 능력치를 정합니다.
- `fire`: chaser
- `electric`: shooter
- `water`: swooper
- `earth`: charger

`KEYS` 개념:

- 점프: `SPACE`
- 흡입: `Z`
- 뱉기: `X`
- 빔 공격: `V`
- 삼키기: `DOWN`

### @game/load.py

역할:

- 이미지 로딩 경로를 통일합니다.
- 한글 폰트를 시스템에서 찾아 반환합니다.

중요:

- `IMAGE_ROOT`는 `@game/src/assets/images`를 가리킵니다.
- `load.load_image(name)`은 `assets/images` 아래 파일만 쉽게 불러옵니다.
- `@game/src/object.py`, `@game/src/setting.py`처럼 `assets/scenery`를 쓰는 파일은 별도 `Path`로 직접 로딩합니다.

## 5. 타이틀 화면과 난이도 선택

### @game/src/title_screen.py

역할:

- 게임 시작 전 타이틀 메뉴를 보여줍니다.
- `START`, `INSTRUCTIONS`, `QUIT` 액션을 관리합니다.
- 마우스 hover/click과 키보드 조작을 모두 지원합니다.

주요 클래스:

- `TitleAction`
- `TitleButton`
- `TitleMenu`

개념:

- `TitleAction`은 메뉴가 반환할 수 있는 결과입니다.
  - `START`
  - `INSTRUCTIONS`
  - `QUIT`
- `TitleButton`은 실제로 보이는 버튼 이미지를 직접 그리지는 않습니다.
  - 메뉴 배경 이미지 자체에 글자가 있으므로, 투명한 클릭 영역만 가집니다.
  - 마우스가 버튼 영역 위에 있고 클릭하면 해당 action을 반환합니다.
- `TitleMenu`는 현재 선택된 메뉴 인덱스에 따라 `menu1.png`, `menu2.png`, `menu3.png`를 배경으로 보여줍니다.

흐름:

```text
show_title_screen()
  -> 이벤트 처리
  -> 키보드 입력이면 selected_index 변경
  -> 마우스 위치가 버튼 위면 selected_index 변경
  -> START면 TitleAction.START 반환
  -> INSTRUCTIONS면 show_instructions() 실행 후 다시 메뉴
  -> QUIT면 TitleAction.QUIT 반환
```

### @game/src/setting.py

역할:

- 난이도 선택 화면을 담당합니다.
- 현재는 보내준 3장 이미지로 화면을 바꿔 보여줍니다.

주요 값:

- `DIFFICULTY_ORDER = ("easy", "normal", "hard")`
- `DIFFICULTY_IMAGES`
- `DIFFICULTY_LABELS`

이미지 매핑:

- `easy` -> `ChatGPT Image ... 09_17_56.png`
- `normal` -> `ChatGPT Image ... 09_26_19.png`
- `hard` -> `ChatGPT Image ... 09_22_20.png`

조작:

- `↑`, `W`, `→`, `D`: 난이도 한 단계 올림
- `↓`, `S`, `←`, `A`: 난이도 한 단계 내림
- `ENTER`, `SPACE`: 선택 확정
- `ESC`: 취소/종료

중요 개념:

- 이미지가 1672x941이라 게임 화면 1000x600에 맞춰 비율 유지 스케일링합니다.
- 이미지는 화면 가운데 배치됩니다.
- 하단에는 현재 난이도와 조작 안내를 텍스트로 덧그립니다.

### @game/src/start_screen.py

현재 상태:

- `import pygame as pg`만 있는 미완성/미사용 파일입니다.
- 현재 실행 흐름에서는 사용되지 않습니다.
- 시작 화면은 `@game/src/title_screen.py`가 담당합니다.

## 6. GameState: 게임 상태 보관소

### @game/src/game_state.py

역할:

- 한 게임 세션에서 계속 변하는 상태를 들고 있습니다.
- 플레이어, 스테이지, 적 목록, 투사체 그룹, 카메라 위치, 데미지 숫자를 관리합니다.

주요 필드:

- `difficulty`
- `ground_y`
- `projectiles`
- `enemy_projectiles`
- `damage_numbers`
- `camera_x`
- `player`
- `stage`
- `enemies`

주요 함수:

- `_create_run(difficulty, ground_y)`
- `GameState.restart()`
- `GameState.enter_stage(enemies)`
- `GameState.update_camera(reset=False)`
- `GameState.update_damage_numbers()`

개념:

- `GameState`는 게임 전체를 담는 “현재 상태 객체”입니다.
- `@game/src/gameplay.py`는 이 상태를 업데이트합니다.
- `@game/src/game_renderer.py`는 이 상태를 읽어서 화면에 그립니다.

스테이지 입장 흐름:

```text
StageManager가 다음 스테이지 enemies 반환
  -> GameState.enter_stage(enemies)
    -> 적 목록 교체
    -> 투사체 비우기
    -> 데미지 숫자 비우기
    -> 카메라 초기화
    -> 플레이어 월드 경계/스폰 위치 갱신
    -> 플레이어 위치 리셋
    -> 짧은 무적 시간 부여
```

카메라 개념:

- 게임 월드는 화면보다 넓습니다.
- 플레이어 중심이 화면 중앙에 오도록 `camera_x`를 계산합니다.
- 렌더링할 때 월드 좌표에서 `camera_x`를 빼면 화면 좌표가 됩니다.

```text
screen_x = world_x - camera_x
```

## 7. 입력 처리

### @game/src/game_input.py

역할:

- Pygame 이벤트 큐를 읽어서 게임에서 쓰기 쉬운 `FrameInput` 객체로 바꿉니다.

`FrameInput` 필드:

- `quit_requested`
- `spit_pressed`
- `gulp_pressed`
- `punch_pressed`
- `kick_pressed`
- `enter_pressed`
- `restart_requested`

개념:

- 계속 누르고 있는 키는 `pg.key.get_pressed()`로 처리합니다.
- “이번 프레임에 한 번 눌렀는지”가 중요한 키는 이벤트에서 `FrameInput`으로 처리합니다.

예:

- `X`: 뱉기, 한 번 누른 순간만 중요
- `DOWN`: 삼키기, 한 번 누른 순간만 중요
- `D/F`: 콤보 공격, 눌린 순간이 중요
- `UP`: 문 입장, 눌린 순간이 중요
- `R`: 게임오버/클리어 후 재시작

### @game/src/koreanize.py

역할:

- 한글 입력 상태에서 키가 이상하게 들어오는 문제를 줄이기 위한 매핑입니다.
- 예를 들어 한글 키보드에서 `ㅋ`이 들어오면 `pg.K_z`처럼 원래 의도한 영문 키로 바꿉니다.

사용 위치:

- `@game/src/game_input.py`에서 `KOREAN_TO_KEY.get(event.unicode, event.key)`로 사용합니다.

## 8. 한 프레임 게임 업데이트

### @game/src/gameplay.py

역할:

- 실제 게임 플레이 한 프레임의 업데이트 순서를 조율합니다.
- 플레이어, 적, 투사체, 전투 판정, 스테이지 전환을 연결합니다.

핵심 함수:

- `update_gameplay(state, actions, keys)`
- `_update_active_stage(state, actions, keys)`
- `_update_stage_transition(state, actions)`

흐름:

```text
update_gameplay()
  -> 플레이어가 게임오버 아니고 스테이지 완료도 아니면
      -> 전환 중이 아닐 때만 active stage 업데이트
      -> 스테이지 전환 업데이트
  -> 카메라 업데이트
  -> 데미지 숫자 업데이트
```

전환 중 처리:

- `state.stage.transitioning`이 True이면 플레이어/적 전투 업데이트를 멈춥니다.
- 대신 스테이지 클리어 애니메이션만 재생됩니다.
- 애니메이션이 끝나면 `StageManager.update()`가 다음 스테이지 적 목록을 반환합니다.

## 9. 플레이어 커비

### @game/src/kirby.py

역할:

- 플레이어 캐릭터의 거의 모든 동작을 담당합니다.
- 이동, 점프, 호버, 흡입, 삼키기, 뱉기, 능력 스택, 빔, 근접 콤보, 체력, 애니메이션, HUD 일부를 관리합니다.

주요 개념:

```text
Kirby
  - 위치: rect, y_float
  - 생존: hp, lives, game_over, invulnerable_until
  - 이동: speed, velocity_y, gravity, is_jumping, facing_right
  - 흡입: inhaling, inhale_range, held_element
  - 능력: ability_stack
  - 투사체 요청: pending_projectiles
  - 빔: _beams
  - 근접 공격: attack_kind, attack_stage, attack_animation, attack_buffer_count
```

중요한 점:

- 커비는 직접 `Projectile` 객체를 만들지 않습니다.
- 커비는 `pending_projectiles`에 딕셔너리를 넣습니다.
- `@game/src/gameplay.py`가 그 딕셔너리를 읽어서 `@game/src/projectile.py`의 `Projectile`로 만듭니다.

### 9.1 능력 스택

관련 메서드:

- `is_empty()`
- `push(element)`
- `pop()`
- `peek()`
- `_push_ability(element)`

개념:

- 커비는 여러 능력을 스택처럼 쌓습니다.
- 가장 오른쪽/마지막 능력이 현재 활성 능력입니다.
- 같은 능력을 다시 넣으면 중복을 제거하고 맨 뒤로 이동시키는 식으로 동작합니다.

흐름:

```text
적 흡입
  -> held_element = enemy.element
↓
DOWN 입력
  -> _on_gulp()
  -> _push_ability(held_element)
  -> held_element = None
↓
V 입력
  -> 현재 peek() 능력으로 빔 사용
```

### 9.2 흡입

### 11.2 Enemy

- `windup`

### @game/src/enemy_system.py

역할:

- 모든 적을 업데이트하기 전에 “이번 프레임에 적극적으로 움직일 적”을 고릅니다.

```text
select_active_enemies()

  -> 난이도별 최대 active 수만 선택

update_enemies()
  -> enemy.update(... engage=enemy in active_enemies)
  -> enemy.pending_projectiles를 state.enemy_projectiles로 이동
```

## 12. 전투 판정

### @game/src/combat_system.py

역할:

- 모든 충돌과 데미지 처리를 한 곳에서 담당합니다.

핵심 함수:

- `resolve_combat(state)`
- `damage_enemy(enemy, amount, source_x, state)`
- `spawn_damage_number(numbers, amount, rect)`

판정 순서:

```text
resolve_combat()
  -> _resolve_projectile_hits()
  -> _resolve_beam_hits()
  -> _resolve_melee_hits()
  -> _resolve_enemy_hits()
```

### 12.1 플레이어 투사체 vs 적

```text
state.projectiles
  -> projectile.rect와 enemy.rect 충돌 확인
  -> enemy.take_damage()
  -> 데미지 숫자 생성
  -> 적이 죽으면 state.enemies에서 제거
  -> projectile.kill()
```

### 12.2 빔 vs 적

```text
player.active_beam_rect
  -> enemy.rect와 충돌 확인
  -> player.beam_damage 적용
  -> beam_hit_cooldown_frames로 너무 빠른 연속 타격 방지
```

### 12.3 근접 공격 vs 적

```text
player.melee_hit_rect
  -> enemy.rect와 충돌 확인
  -> enemy.last_melee_serial로 같은 공격 중복 타격 방지
  -> player.melee_damage 적용
```

### 12.4 적/적 투사체 vs 플레이어

```text
enemy_projectiles
  -> player.rect와 충돌하면 player.take_damage()

enemy.rect
  -> player.rect와 충돌하면 접촉/공격 상태 데미지 적용
```

공격 상태일 때는 `enemy.attack_damage`, 일반 접촉은 `enemy.contact_damage`를 사용합니다.

### @game/src/combat.py

역할:

- 데미지를 입었을 때 뜨는 빨간 숫자 `DamageNumber`를 담당합니다.

개념:

- 생성 위치는 대상 rect 주변에서 약간 랜덤입니다.
- 720ms 동안 살아있습니다.
- 매 프레임 위로 조금씩 올라갑니다.
- 렌더링 시 `camera_x`를 빼서 월드 좌표를 화면 좌표로 변환합니다.

### 13.1 문 입장과 스테이지 클리어

흐름:

```text
플레이어가 문 근처

```

## 14. 배경과 지형지물

### @game/src/object.py

역할:

- 스테이지 배경과 시각 지형지물을 담당합니다.
- 현재 실제 충돌 플랫폼이 아니라 “보이는 오브젝트”입니다.

주요 클래스:

사용 에셋:

`SceneryObject` 개념:

```text
image
x
y
parallax
```

- `x`, `y`는 월드 좌표입니다.
- 그릴 때 `screen_x = x - camera_x * parallax`로 화면 좌표를 계산합니다.
- `parallax`가 1보다 작으면 멀리 있는 것처럼 천천히 움직입니다.

`StageScenery` 렌더 순서:

```text
_draw_sky()
  -> 별하늘 배경 반복
_draw_backdrop_objects()
  -> 멀리 있는 언덕
_draw_ground()
  -> scene1.png 잔디 지형 반복
_draw_route_objects()
  -> 별풀, 크리스탈, 표지판, 떠있는 섬
```

중요 주의:

- `object.py`의 떠있는 섬은 지금은 장식입니다.
- 커비가 올라설 수 있는 실제 플랫폼 충돌은 아직 구현되어 있지 않습니다.
- 실제 플랫폼을 만들려면 `@game/src/kirby.py`의 중력/충돌, `@game/src/enemy.py`의 바닥 처리, 적 스폰 위치까지 함께 바꿔야 합니다.

## 18. 주요 런타임 흐름 상세

### 18.1 시작부터 게임 플레이까지

```text
@game/main.py
  main()
    -> @game/src/game_app.py
       run_game()
          -> pg.init()
          -> display set_mode
          -> show_title_screen()
          -> select_difficulty()
          -> GameState(difficulty, ground_y)
          -> while running
```

사용자가 타이틀에서 START를 고르면:

```text
@game/src/title_screen.py
  show_title_screen()
    -> TitleAction.START 반환
```

그 다음 난이도 선택:

```text
@game/src/setting.py
  select_difficulty()
    -> "easy" | "normal" | "hard" 반환
```

그 다음 실제 게임 상태 생성:

```text
@game/src/game_state.py
  GameState.__init__()
    -> restart()
       -> _create_run()
          -> StageManager 생성
          -> Kirby 생성
          -> 현재 스테이지 적 스폰
```

### 18.2 플레이어가 적을 흡입하고 능력을 얻는 흐름

```text
Z 누름
  -> @game/src/kirby.py Kirby.update()
     -> self.inhaling = True
     -> _handle_inhale(enemies)
        -> inhale rect와 적 rect 충돌 확인
        -> 적 being_inhaled = True
        -> 적이 커비에게 끌려옴
        -> 커비와 닿으면 held_element 저장
```

그 다음:

```text
DOWN 누름
  -> _on_gulp()
  -> ability_stack에 held_element 추가
```

이후:

```text
V 누름
  -> _update_beams()
  -> 현재 능력 peek()
  -> 해당 BeamEffect 활성화
```

### 18.3 투사체로 적을 맞추는 흐름

```text
X 누름
  -> @game/src/kirby.py _on_spit()
  -> _shoot("star")
  -> pending_projectiles에 데이터 추가

@game/src/gameplay.py
  -> pending_projectiles를 Projectile 객체로 변환

@game/src/projectile.py
  -> Projectile.update()로 이동

@game/src/combat_system.py
  -> projectile.rect와 enemy.rect 충돌
  -> enemy.take_damage()
  -> DamageNumber 생성
  -> 적 사망 시 enemies에서 제거
```

### 18.4 적이 플레이어를 공격하는 흐름

```text
@game/src/enemy_system.py
  -> active enemy 선택
  -> enemy.update()

@game/src/enemy.py
  -> AI 타입별 행동
  -> shooter/boss는 EnemyProjectile 생성 가능

@game/src/gameplay.py
  -> enemy.pending_projectiles를 state.enemy_projectiles로 이동
  -> enemy_projectiles.update()

@game/src/combat_system.py
  -> enemy projectile vs player
  -> enemy rect vs player
  -> player.take_damage()
```

### 18.5 스테이지 클리어와 다음 스테이지 전환

```text
플레이어가 문 근처로 이동
UP 입력
  -> @game/src/game_input.py enter_pressed = True

@game/src/gameplay.py
  -> _update_stage_transition()
  -> @game/src/stage.py StageManager.update()
     -> near_goal(player_rect)
     -> goal_unlocked(enemies)
     -> clear_started_at = now
```

그 후:

```text
transitioning True
  -> active gameplay 업데이트 중지
  -> @game/src/game_renderer.py
     -> draw_stage_clear_animation()
```

애니메이션 끝:

```text
StageManager.update()
  -> animation_duration_ms() 경과
  -> _advance()
  -> spawn_current()
  -> GameState.enter_stage()
```

### 18.6 게임오버와 재시작

```text
player.hp <= 0
  -> lives 감소
  -> lives > 0이면 위치 리셋 + HP 회복
  -> lives == 0이면 game_over = True
```

게임오버 상태에서:

```text
R 입력
  -> @game/src/game_input.py restart_requested = True
  -> @game/src/game_app.py main loop
     -> state.restart()
```

## 20. 현재 구조에서 특히 알아야 할 주의점

1. 시각 지형과 실제 충돌 지형은 아직 다릅니다.

`@game/src/object.py`의 떠있는 섬, 표지판, 크리스탈 등은 현재 장식입니다. 커비가 실제로 올라서거나 부딪히지 않습니다. 실제 충돌 플랫폼을 만들려면 `@game/src/kirby.py`의 중력 처리와 `@game/src/enemy.py`의 바닥 처리도 함께 바꿔야 합니다.

2. `@game/src/start_screen.py`는 현재 사용되지 않습니다.

시작 화면은 `@game/src/title_screen.py`가 담당합니다.

3. `@game/load.py`는 `assets/images`만 기본 이미지 루트로 씁니다.

`assets/scenery` 이미지는 `@game/src/object.py`, `@game/src/setting.py`처럼 직접 `Path`로 로딩합니다.

4. `combat_system.py`가 전투 판정의 중심입니다.

커비/적/투사체 파일에도 데미지 관련 정보가 있지만, “누가 누구에게 맞았는가”를 최종적으로 판정하는 곳은 `@game/src/combat_system.py`입니다.

5. 스테이지 전환 중에는 전투 업데이트가 멈춥니다.

`@game/src/gameplay.py`에서 `stage.transitioning`이면 active stage 업데이트를 건너뜁니다. 그래서 춤 애니메이션 중에는 적/투사체/플레이어 이동이 진행되지 않습니다.

6. 적이 죽으면 `state.enemies` 목록에서 제거됩니다.

`@game/src/combat_system.py`의 `damage_enemy()`가 적 사망 시 목록에서 제거합니다. 그래서 스테이지 클리어 조건이나 보스 클리어 조건은 현재 남아있는 적 목록을 기준으로 동작합니다.

7. 보스는 흡입되지 않습니다.

`@game/src/enemy.py`에서 `self.inhaleable = not is_boss`로 설정합니다.
